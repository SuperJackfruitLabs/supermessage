## What it holds itself to

**Agents are participants.** An agent's turn, a permission request and an approval gate each render
as themselves in the timeline, not as a JSON blob and not in a side panel. See
[Working with agents](/use/agents/).

**Still just Matrix.** Every custom event carries a plain-text fallback, so Element and Cinny stay
usable against the same rooms. Nothing here locks a room to this client. See
[Concepts](/start/concepts/).

**Answered is not resolved.** Approving a gate sends a decision; only the board's receipt closes
it. Until then the card says *waiting for the board*. See
[Answered is not resolved](/use/agents/#answered-is-not-resolved).

**Answerable from the Lock Screen.** On iOS a permission request gets its own Allow and Reject,
and a widget can answer a gate in place. A message push carries ids, not words: your device fetches
and decrypts the event and words the notification itself. This path has not yet been verified end to
end on a physical device. See [Notifications](/use/notifications/).

**Encrypted by default, with one exception.** End-to-end encryption through the Matrix Rust SDK
and vodozemac. A room you create with an agent invited is left unencrypted so the agent can read
it. See [Encryption](/use/encryption/).

**One core, five platforms.** iOS, Android, Windows, macOS and Linux. We keep the Matrix decisions
in one Rust core; SwiftUI on iOS, Compose on Android and a Svelte desktop app each render them.
